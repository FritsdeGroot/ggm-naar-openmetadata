# 5. Validatie na elke run

## Snelle controle via logbestand

Schrijf de output weg voor controle achteraf:

```bash
python3 ggm_objecttypen_naar_openmetadata.py --versie v2.5.1 \
  --alle --met-attributen --met-relaties \
  2>&1 | tee run_$(date +%Y%m%d_%H%M%S).log
```

Controleer daarna:

```bash
# Totaal aantal fouten
grep -c "FOUT" run_*.log

# Fouten die geen relatedTerms-koppelingen betreffen (dit zijn de écht problematische)
grep "FOUT" run_*.log | grep -v "relatedTerms"

# Hoeveel objecttypen zijn aangemaakt / bestonden al
grep -c "aangemaakt" run_*.log
grep -c "bestaat al" run_*.log

# Hernoemingen en verwijderingen uit de correctie-pass
grep -E "Hernoemd|Verwijderd|WAARSCHUWING" run_*.log
```

> **relatedTerms-fouten bij de eerste run** zijn normaal: de doelterm bestond nog niet op het moment van koppelen. Een tweede run herstelt dit automatisch (idempotent).

## Controleren via de OpenMetadata-API

```bash
GLOSSARY_ID=$(curl -s -H "Authorization: Bearer $OM_JWT_TOKEN" \
  "$OM_HOST/api/v1/glossaries/name/GGM_Objecttypen" \
  | python3 -c "import json,sys; print(json.load(sys.stdin)['id'])")

# Alle termen ophalen en tellen
curl -s -H "Authorization: Bearer $OM_JWT_TOKEN" \
  "$OM_HOST/api/v1/glossaryTerms?glossary=$GLOSSARY_ID&limit=1000&fields=name" \
  | python3 -c "
import json, sys
data = json.load(sys.stdin)
terms = data['data']
print('Totaal termen:', len(terms))
" 
```

## Controleren via de UI

Ga naar de glossary `GGM_Objecttypen` in OpenMetadata. Het tabblad **"Termen"** toont het totale aantal termen (objecttypen + attribuut-children). Verwacht na een volledige run met `--met-attributen`:

- Objecttypen zichtbaar per domein, met hun subdomein-koppeling
- Attribuut-child terms zichtbaar onder elk objecttype (naam: `"<Objecttype> <Attribuut>"`)
- Objecttypen met relaties hebben een `**Relaties:**`-sectie in de beschrijving en klikbare `relatedTerms`-links

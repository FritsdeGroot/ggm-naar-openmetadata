# 10. Relaties tussen objecttypen (uml:Association)

## Gebruik

```bash
python3 ggm_objecttypen_naar_openmetadata.py --versie v2.5.1 --alle --met-attributen --met-relaties
```

Bij al bestaande objecttypen (eerder geladen zonder `--met-relaties`) voeg je `--forceer-omschrijving` toe:

```bash
python3 ggm_objecttypen_naar_openmetadata.py --versie v2.5.1 \
  --alle --met-attributen --met-relaties --forceer-omschrijving
```

## Wat wordt geladen?

De XMI bevat 1084 `uml:Association`-elementen. Hiervan verbinden ~425 twee herkenbare objecttypen uit de GGM-set. Per relatie wordt:

1. Een `**Relaties:**`-sectie toegevoegd aan de beschrijving van elk betrokken objecttype, met naam en multipliciteit:

   ```
   **Relaties:**
   - heeft (0..*) Aanwezige Deelnemer
   - is (0..1) Indiener
   ```

2. Een `relatedTerms`-koppeling gelegd tussen de twee objecttype-termen (klikbaar in de UI, type: `relatedTo`)

## Multipliciteiten

EA-encoding wordt genormaliseerd:

| XMI-waarde | Weergave |
|---|---|
| `0..-1` | `0..*` |
| `1..-1` | `1..*` |
| `0..0`, `-1..-1` | _(weggelaten)_ |

## Associations zonder naam

Associations zonder naam in de XMI worden weergegeven als `"heeft relatie met"`.

## Extractie: `ggm_relaties_per_object.json`

`extract_ggm.py` genereert `ggm_relaties_per_object.json`: per objecttype een lijst van relaties met naam, multipliciteit en doelobjecttype. Elke relatie levert twee regels op (één vanuit elk perspectief).

## Volgorde-afhankelijkheid

Net als bij attribuut-`relatedTerms` kan een koppeling alleen worden gelegd als de doelterm bestaat. Bij de eerste run worden sommige koppelingen overgeslagen; een tweede run herstelt dit.

## Niet elk objecttype heeft relaties

~575 van de ~947 objecttypen (60%) hebben geen relatie in de XMI — met name referentielijst-objecttypen (Land, Valuta, Provincie etc.). Voor deze objecttypen heeft `--met-relaties` geen effect.

# 3. Scenario A — Nieuwe gemeente (zelfde GGM-versie)

Dit scenario geldt wanneer een andere gemeente dezelfde aanpak wil hergebruiken, met hetzelfde GGM-model maar een eigen OpenMetadata-omgeving.

## Wat blijft gelijk

De volgende bronbestanden zijn gemeente-onafhankelijk en kunnen ongewijzigd worden hergebruikt, mits dezelfde GGM-versie wordt gebruikt:

- `ggm_definities.json`
- `ggm_pad_naar_domain.json`
- `ggm_naam_disambiguatie.json`

De gegenereerde bestanden (`ggm_objecttypen.json`, `ggm_attributen.json`, `ggm_relaties_per_object.json`, `ggm_domeinen_skos.jsonld`) worden opnieuw aangemaakt door `extract_ggm.py`.

## Stappen

**Stap 1 — Repository ophalen**

```bash
git clone https://github.com/FritsdeGroot/ggm-naar-openmetadata-.git
cd ggm-naar-openmetadata-
```

**Stap 2 — Bronbestanden genereren**

```bash
python3 extract_ggm.py --versie v2.5.1
```

Dit downloadt de GGM XMI van GitHub en genereert alle JSON-bronbestanden in `data/v2.5.1/`.

**Stap 3 — Omgevingsvariabelen instellen**

```bash
export OM_HOST="http://<jouw-openmetadata-ip>:8585"
export OM_JWT_TOKEN="<jwt-token-van-de-bot>"
```

**Stap 4 — Eerst testen op een klein domein**

```bash
python3 ggm_naar_openmetadata_domains.py --versie v2.5.1
python3 ggm_objecttypen_naar_openmetadata.py --versie v2.5.1 --domein "Economie" --met-attributen --met-relaties
```

Controleer in de OpenMetadata-UI of het domein, de objecttypen en attributen correct zijn aangemaakt.

**Stap 5 — Alles laden**

```bash
python3 ggm_objecttypen_naar_openmetadata.py --versie v2.5.1 --alle --met-attributen --met-relaties \
  2>&1 | tee run_$(date +%Y%m%d_%H%M%S).log
```

**Stap 6 — Tweede run voor relatedTerms**

Sommige `relatedTerms`-koppelingen worden bij de eerste run overgeslagen omdat de doelterm nog niet bestond. Een tweede run herstelt dit:

```bash
python3 ggm_objecttypen_naar_openmetadata.py --versie v2.5.1 --alle --met-attributen --met-relaties
```

**Stap 7 — Valideren**

```bash
grep -c "FOUT" run_*.log
grep "FOUT" run_*.log | grep -v "relatedTerms"
```

Zie [Validatie](5.-Validatie) voor meer details.

## Gemeente-specifieke aanpassingen (optioneel)

- Afwijkende domeinnamen → pas `DOMAIN_FQN_OVERRIDES` aan in `ggm_objecttypen_naar_openmetadata.py`
- Bepaalde objecttypen uitsluiten → filter `ggm_objecttypen.json` of voeg een uitsluitingslijst toe
- Eigen objecttypen toevoegen → voeg toe aan `ggm_objecttypen.json` met dezelfde structuur en controleer op naamcollisies
